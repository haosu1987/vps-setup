# 连接故障诊断

客户端使用 Happ。先区分单设备问题、所有设备问题与服务端问题，保留当前可用配置，不反复切换协议或重装软件。

| 现象 | 检查顺序 |
| --- | --- |
| 所有设备均无法代理 | 服务端 active、代理监听、主机与云规则，再核对节点参数 |
| 单设备连接失败 | Happ 导入的节点、独立凭据、Flow、SNI 与设备网络 |
| 国内异常、国外正常 | Happ 分流与国内 DNS，核对具体失败域名 |
| 国外异常、国内正常 | 节点有效性、服务端出口、代理 DNS |
| 面板打不开、代理正常 | SSH 隧道及回环管理面；不要开放公网面板 |
| 首页正常、图片或视频异常 | 实际依赖域名、DoH、UDP/QUIC；首页成功不代表完整可用 |

服务端在同次渲染的完整工作区执行：

```bash
sudo bash scripts/proxy/proxyctl.sh doctor
```

普通用户诊断会跳过受保护配置审计。结构检查通过不等于端到端连接通过；继续从 Happ 核对目标访问与出口。服务端测量 `server-direct` 仅反映服务器本身访问目标。

不再使用旧 `proxy.sh`、TUN、DNS 候选或客户端验收脚本。旧客户端已卸载，其历史恢复命令不适用于 Happ。

反馈只提供脱敏状态、时间范围和错误类别，不粘贴节点链接、二维码、面板路径、凭据、Cookie 或原始日志。
